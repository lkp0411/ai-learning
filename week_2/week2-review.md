## 2. CIFAR-10 卡在哪一步

### 坎一：语法和结构错误，一共 5 处

刚写完第一次跑，报 `SyntaxError`。修完一个又冒一个，连着五个：

```python
def CifarCNN(nn.Module):                    # ① def 应该是 class
nn.Conv2d(3.32, kernel_size=3, padding=1)   # ② 少了个逗号，3.32 成了浮点数
def duild_model():                          # ③ 拼错，duild → build
for images,labels in train_loader():        # ④ DataLoader 后面多了括号
optimizer.zero_gard()                       # ⑤ grad 拼成 gard
```

这些都算「便宜的错」——报错位置精准，一看就懂。第 ② 个最阴，`3.32` 看着像正经的浮点数，实际上是 `3, 32` 打错了。

### 坎二：数据集下不动，170 MB 下了 25 分钟

这个最没有技术含量，但也最耗时。

CIFAR-10 的官方源在多伦多大学（`cave.cs.toronto.edu`），国内直连实测 **4 KB/s**，按这个速度要 **12 小时**。换成代理后 123 KB/s，25 分钟下完。

中途我一度以为程序卡死了——`data/` 目录十分钟只涨了 5 MB，python 进程占了 579 MB 内存但 CPU 只用了 2.8 秒，GPU 占用 0%。这些数字其实已经把答案写在脸上了：**它没在算，它在等网络**。学会看这几个指标比什么都快。

### 坎三：学习率太大，模型完全学不动

这个是真正卡住的，因为它**不报错**。

第一次完整跑 20 轮，结果是：

```
Epoch 01 | Val Loss: 2.3035 | Val Acc: 10.00%
Epoch 02 | Val Loss: 2.3035 | Val Acc: 10.00%
Epoch 03 | Val Loss: 2.3031 | Val Acc: 10.00%
Epoch 04 | Val Loss: 2.3043 | Val Acc: 10.00%
连续 3 轮未提升，触发早停！
```

准确率 10% 是 10 类分类的随机水平，等于没学。关键线索是 **`loss = 2.3035`**，而 `ln(10) = 2.3026`——这是"十个类别概率完全均等"时的交叉熵。损失一点没动，说明网络输出恒定，梯度已经推不动它了。

原因是 `LR = 0.01` 对 Adam 来说太大了（常规是 0.001）。更新步子迈太大，ReLU 神经元被一把推到负半轴，全部死掉，输出恒为 0，梯度恒为 0，再也活不过来。

改成 `LR = 0.001` 之后：

```
Epoch 01 | Val Acc: 52.47%
Epoch 02 | Val Acc: 62.21%
...
Epoch 20 | Val Acc: 80.12%
```

### 试过但没用的办法

- **反复重跑，指望"这次运气好"**：同样的 `LR=0.01`，第一次跑出了 39.2%，第二次就是 10.0%。当时我以为是自己代码有问题，其实是学习率处在崩溃边缘——这种"时好时坏"本身就是学习率过大的信号，只是我当时没往这上面想。
- **把 epoch 调大**：早停在 4 轮就触发了，加到 100 轮也没用，因为模型压根没在学。
- **怀疑是数据增强的锅**：RandomCrop + Flip 会不会把图搞坏了？后来做了对照实验（去掉增强和 Dropout，其余完全不变跑 20 轮），结果是验证准确率 **75.23%**，比带增强的 80.12% 还低 4.9 个百分点，训练/验证差距从 3.24 拉到 22.65。结论：不是增强的锅，增强反而在救命。

## 3. 「验证集」到底是什么

用自己的话说：

**训练集是课本，验证集是模拟考，测试集是高考。**

- **训练集**：模型看着这些数据改参数，它就是"见过答案"的
- **验证集**：模型从没见过，用来在训练过程中**模拟考**，看它是真的学会了还是在背答案
- **测试集**：最后交卷用的，全程不参与任何决策，只用来看最终成绩

### 为什么非要划分验证集

因为**训练集上的成绩会骗人**。

举个极端的例子：如果一个模型把训练集 5 万张图全背下来了（死记硬背每张图的像素），训练准确率能到 100%，但它遇到新图就完全瞎猜。这种情况叫**过拟合**。如果只看训练集，你会以为模型完美了，实际上它什么都没学会。

验证集的作用就是**当那个"没见过的题"**，让过拟合无处遁形。训练准确率 95%、验证准确率 60%，这个 35 个百分点的差距就是过拟合的体温计。

### 为什么存"最好的模型"要按验证集算

这是这周我最开始没想明白的地方。

训练循环里那句：

```python
if val_acc > best_acc:
    torch.save(model.state_dict(), "best.pt")
```

为什么不是按 `train_acc`？

因为**训练准确率是个只会涨不会跌的指标**（只要不崩），它永远在最后几轮最高。如果按训练集存，你存下来的永远是"最后一轮的模型"，而最后一轮往往已经过拟合了——它在训练集上越来越准，在验证集上开始变差。

而验证集准确率是有起伏的：它会先涨，涨到某个点之后开始回落。**那个最高点，才是模型泛化能力最好的时刻**。所以必须盯着验证集存，而不是训练集。

这也是为什么代码里要有早停（patience）——连续 3 轮验证集不涨了，说明后面再练也只是在背题，可以停了。
